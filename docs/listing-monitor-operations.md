# Hosted free-listing monitoring

Vercel invokes `/api/cron/listings` daily at 08:00 UTC (09:00 London during this window), using the existing `CRON_SECRET`. Collection runs from 12 October until **16 October 2026 at 00:00 UTC**, covering the next three daily checks on 13–15 October. After the deadline the endpoint returns inactive before any database or directory requests. The cron configuration remains a harmless daily no-op until removed in a later deployment.

Each run stores one dated snapshot in the service-only `marketing_event_log` under `listing_monitor_snapshot`, marked internal. The existing acquisition allowlist excludes these records from audience metrics. The daily key makes retries replace that day's snapshot instead of creating duplicate records. No new database schema, paid service, model call or outbound message is required. Existing hosting usage still applies.

Authenticated analytics administrators can read the most recent twenty snapshots at `/api/analytics/listings`. The response contains aggregate campaign metrics and public listing evidence, never subscriber identities. The cron endpoint requires the secret and runs collection only in production.

Acquisition uses the existing first-touch report for `mb_free_listings`, cumulative from 12 October and for the last seven days bounded by that start. It retains the existing bot, internal, test and unverified historical exclusions and deduplicates newsletter subscribers across markets. Incomplete datasets produce unavailable metrics rather than zeros. Missing consent and attribution remain limitations. Newsletter records do not establish verified email addresses or engagement.

Public checks inspect the five submitted directories for actual website links, following at most two same-origin Macro Bias profile links. They never fetch the Macro Bias destination. Published links are checked for source, medium and campaign parameters. Requests have time and response-size limits; redirects cannot leave the fixed directory origin. Script text, lookalike domains and a missing item are not publication evidence. Dynamic pages, pagination, provider blocking and links behind a directory redirect can prevent detection; `not_observed` does not mean rejected or absent. First observed live time is separate from an approval date.

**Mailbox limitation:** this job has no Microsoft Graph/Outlook credentials. It does not read inbox-only approvals or rejections or authenticated InboxReads dashboard state. An Outlook plugin connection by itself does not grant this Vercel job mailbox access. Public publication monitoring and subscriber snapshots continue while the laptop is off; local chat notifications and browser mailbox checks still require the app. Do not describe this as full cloud mailbox monitoring.

Validation: `node scripts/verify-listing-monitor.cjs`, `npm run verify:analytics`, `npm run typecheck`, `npm run build`. After deployment, invoke the protected production route once and confirm the saved snapshot using the existing service account. Check the deployed Vercel project cron configuration independently of the source file. Keep the existing chat monitor as a report reader, avoiding duplicate collection while the hosted window is active.
