# X commentary acquisition test, 28 October–10 November 2026

The owner authorized automatic X publishing, public briefing improvements and subscriber tracking on 27 October. This is a new, bounded server experiment. The expired `/api/marketing/grok-x` publisher and paused Grok/Reddit/chat routines remain unchanged. No credentials are given to Grok or a new third party.

## Automatic delivery

Vercel calls `/api/cron/x-test` once per weekday, scheduled at 15:00 UTC and authenticated with its existing CRON_SECRET. The existing Hobby plan can start that run anytime from 15:00 through 15:59; exact minute precision is not promised. Only `VERCEL_ENV=production` plus `X_COMMENTARY_MODE=live` permits writes/publication. `?preview=1` is read-only, even in production; it checks actual X account identity and both current market previews. No browser automation posts to X. No hosting upgrade is required.

The fixed publishing interval is 28 October 00:00 UTC through 11 November 00:00 UTC (14 days). Stocks publish Tuesday/Thursday; crypto Wednesday/Friday. Planned dates: crypto 28/30 October, 4/6 November; stocks 29 October, 3/5/10 November. This is four posts per newsletter. Nothing is scheduled on other dates, outside 15:00–15:59 UTC, or after the interval. The job makes one bounded retry after two seconds for a temporary data/read-only identity failure before sending; it cannot resend an uncertain API outcome. There is no backlog or catch-up burst. Publication does not depend on the laptop, this chat, a Grok computer, or a manual draft approval.

Only verified completed-session price comparisons can publish: stock facts must be the prior completed weekday and crypto facts yesterday UTC, attached to a fresh publication generated today. Facts have matching dates/tickers, positive closes and internally consistent returns. No paid article body, AI-generated causes, breaking-news claims or scores substitute for commentary. The copy describes an observed move, a relevant comparison and what to watch next. Missing/stale data or oversized copy blocks the slot with a saved reason. Account identity must be `macro_bias`; no new app, credits purchase or permission expansion is involved.

The existing service-only marketing_event_log stores `x_commentary_delivery` receipts. A deterministic primary-key claim per experiment/market/UTC date precedes the X API call. A claim, timeout, missing remote receipt or failed receipt update blocks automatic resend. Review the actual timeline before any recovery; never delete a claim and blindly retry. Provider error bodies and tokens are not logged. `x_commentary_run` records the latest slot result, including pre-send blocks. Both event types are excluded from genuine-growth analytics.

## Acquisition and evaluation

Every post links to its own public dated summary, with `utm_source=x`, `utm_medium=organic_social`, `utm_campaign=mb_x_commentary_20261028`, and `utm_content=<stocks|crypto>_<YYYYMMDD>` for the publishing date. The original consent-aware acquisition collector persists those touches through the signup. Unique subscribers choosing both count once overall and once in each newsletter column. Internal traffic, tests, bots, duplicates/reactivations and unverified legacy conversions retain their existing exclusions. No synthetic subscribers or visits are used for verification.

`/analytics/x-test` is owner-only and shows all eight slots, delivery links/blocks, first-touch campaign acquisition, separately labeled latest-touch assists, original newsletter preferences, per-post UTM-content acquisition and daily sampled X impressions. Broad stock/crypto content groups remain separate from per-post attribution. Never sum assists with first-touch conversions or distinct visitors across posts. Missing consent, unknown attribution, incomplete reads and unavailable X metrics do not establish zero real traffic. Newsletter records do not prove verification, engagement or ROI.

Each live weekday run saves a daily `x_commentary_growth` checkpoint. Complete same-day checkpoints are reused on duplicate invocations to limit analytics/API reads. It records first/latest aggregates and one batch of available public X metrics; denied/missing engagement access is unavailable rather than zero. An incomplete acquisition checkpoint can be retried. A final checkpoint runs 11 November; from 12 November all invocations are no-ops. The cron entry remains installed with these hard bounds. Existing acquisition collection continues recording later arrivals; the read-only owner report includes them. Outlook/listing workers remain stopped.

On 27 October the owner requested follow-up monitoring for this test. The existing paused chat heartbeat was repurposed to this X experiment only: daily at 16:10 UTC, ending 11 November. It verifies due receipts, independently checks the first remote post, and reports first publication, new attributable subscribers/first paid conversions, meaningful changes and actionable failures. It does not publish, resend or remove uncertain claims. `docs/x-test-monitor-state.json` retains the last complete aggregate baseline and notification state; unavailable reads must not overwrite complete metrics with zero. Vercel publishing/checkpoints run with the laptop off; this local chat follow-up needs its local execution environment. No cloud chat notification delivery is configured.

Run `node scripts/report-x-experiment.cjs` for an authorized aggregate report. The 27 October prelaunch read is a setup baseline, not evidence of campaign performance. Evaluate successful deliveries and exposure first, then visits, unique new subscriptions, and verified first paid conversions. Eight posts with negligible reach would be an exposure result, not enough evidence to reject the newsletter's value. Review missed slots as operational failures. Renew or change publishing only on a new owner instruction.

## Search discovery

All login variants return `noindex,follow` and canonical `/login`; robots.txt deliberately allows Google to crawl those URLs and discover noindex. Robots and sitemap use the configured canonical host. The public dated stock/crypto pages retain self-canonicals and now include price-only, dated summaries, a meaningful market comparison, explicit next-session references and a market-default free newsletter form. Full briefing, model and news access remain gated. Metadata reuses the same public summary; no private body is fetched for previews. Missing/inconsistent quotes omit the summary rather than inventing facts. Existing publication timestamps remain unchanged.

Search Console validation requests trigger Google's review, not immediate indexing. Google independently decides whether to index an article; improved summaries cannot guarantee inclusion of all previously excluded dates. Do not request indexing for login URLs or treat expected redirects/alternate canonicals as errors.

Validation: `node scripts/verify-public-briefing-summary.cjs`, `node scripts/verify-x-experiment.cjs`, `node scripts/verify-grok-x-publishing.cjs`, `npm run verify:analytics`, `npm run verify:distribution`, `node scripts/verify-briefing-data.cjs`, `npm run typecheck`, `npm run build`, then rendered anonymous desktop/mobile checks of both actual dated summaries and login metadata. Preview checks never claim or post.
